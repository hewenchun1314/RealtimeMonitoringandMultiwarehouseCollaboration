# 前端 E2E 公共操作手册

接到需求或 Bug 后，先读禅道原单描述里的页面、复现或验收步骤和预期结果，再按下面的公共步骤准备环境。测试 Agent 将原单要求转成该工单的页面场景。

## 登录和选工区

1. 用本单的候选版本启动前端，使用配对的测试 Chrome。默认登录地址为 `http://localhost:5000/aggregation-platform/sso/login`，账号为 `hewenchun`。执行器可使用 Chrome 对该账号的自动填充，或读取项目本地 `.local/e2e-login.json` 的 `username` 和 `password`。需要额外认证时记录「等待登录」。
2. 登录后打开 `/aggregation-platform/sso/home-page/work-area`，点击工区全名为「海能发陆上示范区工区」的行。确认该行已选中，再去原单指定的业务页面核对页头工区。原单明确指定其他工区时，以原单为准。
3. 原单允许任意数据或未限定样本时，选择当前工区中有数据的案例和井。当前井缺少用例所需的数据时换井，当前案例没有合适的井时换案例。记录最终选用的名称。原单指定了复现样本时按指定样本验证。

## 在业务页面验证

- 原单可以填写线上完整链接或以 `/` 开头的页面路径。把页面地址填入场景的 `entry_path` 或 `navigate.path`。验收执行器会把项目配置 `e2e.source_origins` 中的线上地址转换成本次候选服务的本地地址，保留路径、查询参数和锚点。例如 `http://10.10.4.140:31111/aggregation-platform/shell-hub/data-overview/gas-profile` 会在默认环境访问 `http://localhost:5000/aggregation-platform/shell-hub/data-overview/gas-profile`。未配置的完整链接会报告场景输入受阻。
- 有数据的用例先按原单完成数据选择，等到页面出现真实记录、数值或曲线后，再执行本单的业务断言。将等待实际数据的步骤写入场景的 `wait-for`，保存页面读到的值。找不到可用数据时记录「测试数据受阻」和已查范围。
- 空状态用例按原单指定的空条件验证。涉及保存或覆盖数据时，使用原单指定的可写样本及恢复方式。
- 回执记录候选版本、实际工区、实际样本、操作和结果。运行器、超时和回执格式见 [E2E 阶段指引](../.agents/skills/zentao-autodelivery/references/e2e.md)。

## 禅道原单怎么写

在需求描述的「验收条件」或 Bug 描述的「复现步骤、预期结果」写明三件事：

1. 打开哪个页面，要测试什么。
2. 怎样操作；如需特定案例、井、记录或初始状态，在这里注明。允许任意有效样本时可写「任意有数据的案例和井」。
3. 页面上看到什么才算通过。涉及数据的场景，写清能证明数据已加载的信号，以及最终要核对的业务结果。
