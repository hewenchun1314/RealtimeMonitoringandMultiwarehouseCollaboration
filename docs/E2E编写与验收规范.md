# E2E 编写与验收规范

版本 1.0 · 适用于页面、服务及跨系统业务流程

E2E 用例从用户或调用方实际使用的入口触发操作，验证业务结果能在最终使用位置观察或回读。交接时，另一位测试人员或自动化 Agent 应能按文档准备数据、独立重跑并判断结果。

## 一、确定测试范围

每条用例围绕一个业务场景，注明用例编号、关联需求或验收项（AC）、涉及模块及是否本期必验。单个模块的用例应能独立执行。跨模块联合用例从真实入口走完整主链路，验证各模块如何把数据和状态交给下一环节。

| 场景 | 什么时候写 |
| --- | --- |
| 主流程 | 从实际入口到业务完成，至少覆盖一条可独立重跑的主流程。 |
| 数据及界面状态 | 有数据、空数据、失败表现不同时，分别写触发条件和可见结果。加载中或等待完成会改变用户操作时，也写明预期。 |
| 关键分支 | 按本期规则覆盖取消、权限不足、校验失败、重试、重复提交或批量部分失败等会改变业务结果的场景。 |
| 回归和联合验收 | 明确要保留的旧行为，以及哪些模块交接后需要串起来验证。 |

## 二、写清一次运行需要什么

- **环境和入口。** 写明测试环境、项目及完整菜单路径，提供可用路由或服务触发入口。明确待验前后端版本、所需服务、账号角色和权限。账号密码、令牌用环境配置或凭据引用。
- **初始状态。** 写明用例开始时所在页面、已选对象、记录状态、开关等会影响结果的条件。涉及嵌入页面或新标签页时，写清从哪个入口进入、用什么标志确认页面已到达。
- **测试数据。** 用稳定 ID、唯一名称或可重复创建的夹具定位。写清准备方式、初始值和数据量下限。多组数据用编号列出各自输入及预期。并行或重试时使用可区分的专用数据，记录每次运行标识。
- **数据恢复。** 保存、覆盖、删除、归档等场景先核对测试对象和初始状态。写出成功或失败后的清理或恢复步骤，以及恢复后如何复查。跨系统写入需说明涉及哪些系统的数据。

## 三、逐步描述操作和断言

每步写成 **操作前检查 → 执行动作 → 操作后断言**。写明点击的控件、输入值、选择规则以及等待哪个可观察状态。异步计算、保存或同步应等到规定的结果状态，或达到预先约定的超时条件。

| 验证对象 | 应记录的可观察结果 |
| --- | --- |
| 界面和交互 | 目标页面、提示位置和内容、字段值、条数、按钮状态、弹窗或跳转后的落点。 |
| 接口联动 | 当前动作触发的请求、业务相关的入参和响应字段，以及这些字段在页面上的显示或状态变化。 |
| 写入和跨系统交接 | 刷新、重新进入或到下游系统按唯一标识查询，核对保存后的字段、数量和状态。 |
| 失败或取消 | 失败反馈、原数据和用户输入的处理、能否重试，以及恢复后的状态。 |

把确定的预期写成可比对的值、状态或行为。例如「刷新后，编号对应的记录仍是已保存状态」可以直接验收。「页面正常」需要补充实际观察的对象和结果。

## 四、用例模板

```markdown
# E2E-[编号] [业务场景]

- 关联需求或 AC：[编号；本期必验 / 回归]
- 范围：[涉及的模块或系统]
- 环境与入口：[环境、待验版本、项目和菜单路径或服务入口]
- 角色与前置条件：[角色、凭据引用、服务和初始状态]
- 测试数据：[唯一标识、创建或导入方式、初始值]

| 步骤 | 操作前检查 | 执行动作 | 操作后断言 |
| --- | --- | --- | --- |
| 1 | [页面及控件状态] | [点击、选择或输入] | [具体的页面或接口结果] |
| 2 | [上一阶段的结果] | [刷新、重新进入或从下游回读] | [实际保存的字段、数量或状态] |

- 留证：[截图、脱敏请求与响应或日志；注明对应步骤]
- 恢复：[清理对象、操作入口、复查方式]
```

## 五、完整示例：保存草稿后重新打开

本示例使用虚构功能和数据，业务提示和控件名称按实际产品替换。

- **AC-001。** 新建并保存草稿后，从草稿列表重新进入，能读回相同的标题、内容和草稿状态。
- **环境和数据。** 在测试环境以有创建权限的角色进入「工作台 → 草稿管理」。使用本次唯一标题 `E2E-草稿-[运行编号]` 和内容「验收内容 A」，确认执行前无同名记录。

| 步骤 | 操作前检查 | 执行动作 | 操作后断言 |
| --- | --- | --- | --- |
| 1. 新建 | 草稿列表已加载，「新建」可用。 | 点击「新建」，输入唯一标题和内容。 | 编辑页显示所填值，「保存草稿」可用。 |
| 2. 保存 | 必填字段已填，标题和内容正确。 | 点击「保存草稿」，等待保存完成。 | 显示保存成功，记录处于「草稿」状态。记录返回的 ID 或唯一标题。 |
| 3. 回读 | 已取得本次记录的定位信息。 | 刷新草稿列表，按唯一标识查找并打开。 | 只命中本次记录，标题、内容和草稿状态与保存时一致。 |

留存保存与回读的脱敏证据。执行结束后按本次唯一标识清理专用记录，并重新查询确认已无该记录。保存失败、取消等分支按需求另建用例。

## 六、记录结果与完成判定

| 结论 | 使用条件 |
| --- | --- |
| 通过 | 实际待验版本上的用例已运行，所有必验断言成立并可追溯到证据。 |
| 失败 | 用例已运行，任一必验断言与预期不符。记录失败步骤、预期、实际、证据和已核实的原因。 |
| 待验证 | 环境、版本、权限、数据或前置模块限制导致用例无法完成。记录受影响范围、缺失条件及补验方式。 |

运行记录包含用例编号、实际版本、环境、数据标识、结果、证据位置和数据恢复结果。模拟、只读检查和真实写入各自记录实际覆盖范围。失败用例的后续依赖步骤标记待验证，独立场景可继续。返工、重跑和报告按项目流程处理。整体验收通过须覆盖本期全部必验用例及约定的跨模块场景。
