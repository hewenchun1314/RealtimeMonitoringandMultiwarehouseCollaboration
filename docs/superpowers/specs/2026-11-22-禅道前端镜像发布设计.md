# 禅道前端镜像发布设计

纯前端及前后端工单在前端合回后进入 `frontend.deploy`。成功条件是 Harbor 可读回本单镜像及摘要。本期交付镜像回执，供后续 Rancher 发布消费。

Windows 启动器等待原工单会话及进程组停止，由独立前端发布执行器认领账本阶段。使用领取快照，并在启动前对照当前发布配置、前端工作区和应用授权。前端发布可独立启停。新增工单使用新路线。

## 发布顺序

1. 从 `frontend.plan` 读取应用键，从 `frontend.integration` 读取实际合回 SHA。按应用配置核对仓库根目录和目标分支。逐仓比较远端与合回提交，必要时普通推送，随后再次从远端核验包含关系。登记每仓的合回与远端 SHA。输入分叉或应用信息不完整时记录阻断。
2. 确认本单 Windows 进程组停止。用配置的本地端口核对持有服务均已退出。外部服务仍占用端口时记录阻断，等待所属会话停止后续跑。
3. 从已核实的本地仓库把各应用合回 SHA 检出到独立目录。使用 `customized-release` 的 `zentao-ai-development` 分支配置和显式工作区，对本单应用构建；以配置中固定摘要的大前端镜像作底图，局部替换应用产物。产物推送标签包含工单与版本输入的指纹，后缀为 `zentao-ai-development`。命令显式关闭打包脚本的远端切换行为。
4. 推送前保存镜像配置摘要和预期标签，再从 Harbor 验证配置摘要、架构及镜像摘要。识别到相同回执时可以续跑，已有标签指向其他内容时报告冲突。复用模式要求本单有匹配 SHA 和发布目标的推送记录。

## 进程和恢复

发布在系统 Job 内受控执行。账本尝试、阶段运行证据及原子写入的发布回执存放于本单目录。每仓推送后留下进度。运行中断时先核实原进程已停止并读回本单的远端记录。完成后恢复原工单会话。正式启用需要确认基础镜像摘要、Git 与 Harbor 访问权限。
