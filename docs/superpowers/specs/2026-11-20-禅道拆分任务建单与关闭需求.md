# 禅道需求拆分后的任务创建与关闭

2026 年 11 月 20 日 · 需求确认稿

需求负责人打开原需求所在迭代的「任务」面板，应能看到这张需求拆出了哪些研发任务、每项指派给谁，以及哪些已经验收并合回。拆分 Agent 负责把拆分结果登记为禅道 Task，并在每项达到交付条件后关闭对应的 Task。此规则适用于纯前端、纯后端和前后端三种研发路线。

## 建哪些任务，建在哪里

| 事项 | 业务规则 |
|---|---|
| 建单时机与数量 | 需求评审后，拆分 Agent 确定研发任务清单。每个拆分项创建一张独立 Task，拆出几项就建几张。同一端可以有多张任务。 |
| 项目与迭代 | 每张 Task 归属原需求所在的项目和迭代（禅道「执行」），能在该迭代的「任务」面板找到，并关联原需求 Story。 |
| 初始指派人 | 创建 Task 时读取原需求的指派账号。原需求指派给谁，新建 Task 就指派给谁，前后端任务执行相同规则。 |
| 任务内容与对应关系 | 从 Task 能看出该项要交付什么、属于哪一端、按什么条件验收。每个拆分项都有稳定编号，能据此找到唯一对应的禅道 Task。 |

## 建单、研发和关单如何配合

1. **拆分 Agent 提交清单后，两项工作同时开始。** 工单主会话按原研发路线派发工作，拆分 Agent 逐项创建和跟踪禅道 Task。开发、测试可以在建单期间继续推进。跨端需求可以先登记两端的全部任务，前端开发仍按既有流程在后端交接成功后启动。
2. **测试和合回分别提供证据。** 测试 Agent 记录具体拆分项、独立验收结果和受验版本。工单主会话记录该项涉及的仓库、目标分支及实际合回结果。需要前后端共同证明的业务场景，以对应版本的联合验收结果为依据。
3. **拆分 Agent 逐项关闭。** 一项任务同时满足“该项独立验收通过”和“该项涉及的代码全部合回各自目标分支”时，关闭对应的 Task。一项涉及两个仓库，就要核实两个仓库均已合回。合回内容影响已验收行为时，应补验受影响的场景。
4. **以禅道实际状态确认结果。** 创建后可查到 Task 编号、关联需求、迭代和初始指派人。关闭后可读回「已关闭」状态。仅显示「已完成」时，该项仍有关闭操作待处理。其余尚在开发、验收失败或只合回部分代码的 Task 继续保持打开。

## 验收示例

以下以同一条需求的 **5 个拆分项**为例。假设需求位于 A 迭代，指派给 `DOt-hwc`，拆出 2 项后端任务和 3 项前端任务。

| 场景 | 应观察到的结果 |
|---|---|
| 拆分完成并建单 | A 迭代的任务面板出现 5 张独立 Task，全部关联该 Story，初始指派人都是 `DOt-hwc`。建单期间，主会话已可派发后端开发。 |
| 3 项验收通过且已全部合回，第 4 项只合回部分仓库，第 5 项联合验收失败 | 仅前 3 张为「已关闭」。第 4、5 张仍打开，各自能查到未满足的条件。 |
| 第 4 项剩余仓库完成合回，最终版本验收有效 | 关闭第 4 张。第 5 张保持打开，直至修复后的版本通过联合验收并完成所涉及代码的合回。 |
| 禅道已创建某张 Task，但响应丢失或会话重启 | 恢复后能核对并续接原 Task，同一拆分项只出现一次。若研发先完成，保留该项证据，待核实 Task 编号后再处理关闭。 |

纯前端和纯后端路线分别采用相同的验收口径。例如纯前端拆出 3 项，面板就出现 3 张前端 Task；纯后端拆出 4 项，就出现 4 张后端 Task。每张均按本项的验收和合回结果判断。

## 已确认的异常处理与验收

| 情况 | 处理规则 | 验收示例 |
|---|---|---|
| 原需求未关联迭代，或关联多个迭代且无法唯一确定本单归属 | 拆分 Agent 将受影响的拆分项标记为「待建单」并记录原因，研发继续。归属明确后，在对应迭代逐项补建。 | 5 项任务因迭代不明确而待建。归属明确为 A 迭代后，能在 A 迭代查到对应的 5 张 Task，每项各一张。 |
| 后续联调发现已关闭的 Task 仍有原验收条件未满足 | 拆分 Agent 重新打开原 Task。修复通过独立复验，且涉及的代码全部合回目标分支后，再关闭原 Task。 | 原任务重新打开，返工前后 Task ID 一致。再次满足关闭条件后，读回同一张 Task 的状态为「已关闭」。 |
| 后续新增独立的业务要求 | 拆分 Agent 将新增要求列为新的拆分项，另建一张关联原 Story 的 Task。 | 在原有 5 项均已关闭后新增 1 项独立要求，可查到第 6 张 Task，并能单独跟踪其验收和关闭。 |

现有项目已定义按研发范围拆分、独立验收及逐仓合回的流程。本需求新增的是拆分项在禅道任务面板上的创建、跟踪、关闭及返工重开。开发前需在目标实例核验任务关闭、重新打开及状态读回的操作方式。[现有研发流程](2026-11-20-delivery-scope.md)
