# 禅道拆分任务同步实施计划

依据[实现设计](../specs/2026-11-20-禅道拆分任务同步设计.md)，在现有 SQLite 账本和 Windows 工单执行入口接入 Task 同步。按以下顺序交付，测试使用隔离数据库和模拟禅道端验证并发与故障；目标实例的读取与实际写入分别核验。

| 步骤 | 实现位置 | 验证 |
|---|---|---|
| 1. 禅道客户端 | 新增 task_remote.py，复用现有通用客户端，核对归属、账号、拆分标记、完成、关闭和重开 | 模拟创建与读回、迭代不唯一、分页查重、接口失败 |
| 2. 任务登记和发送顺序 | 新增 task_sync.py，在 ledger.py 扩表，将拆分、修订和逐项证据接入 execution.py | 稳定编号、原子登记、租约互斥、回执丢失、迟到操作 |
| 3. 逐项验证 B | 新增 task_evidence.py，接入阶段计划、独立验收及部分合回 | 同端多项、跨端版本、部分失败、已关任务返工再关闭 |
| 4. 工单和监测入口 | worker.py 管理独立同步执行，监测轮次补办已收尾工单；更新阶段指引及进度页 | 研发与建单并行、旧快照兼容、关单和研发完成分别展示 |
| 5. 联合回归 | scripts 和 tests 位于 .agents/skills/zentao-autodelivery，下同 | 运行 python -B -m unittest discover -s .agents/skills/zentao-autodelivery/tests 及原 Task 客户端测试，核对实际禅道验证范围 |

## 交付验证

- 本地跨端工作流使用临时 Git 仓库，依次经过计划、研发、独立验收及目标分支合回。2 个后端任务和 3 个前端任务中，3 项满足 B，另外 2 项验收失败；账本和远端模拟器均显示对应的 3 张已关闭。
- 同版本隔离禅道 22.6 中，实际创建 5 张 Task，读回关联 Story、执行和指派账号。关闭其中 3 张，再将其中 1 张按原 ID 重开、再次关闭，另外 2 张持续待处理。10 次操作均有读回回执。[本机脱敏回执](../../../.local/verification/split-task-sync/isolated-22.6.json)
- 正式实例使用项目凭据做只读核验。海能发项目的需求 #34 在核验时没有关联执行，属于需求中定义的「待建单」场景。正式定时任务按新领取工单的配置快照生效。
- 正式项目已按授权启用 `runtime.split_task_sync`。使用正式配置和隔离账本走过新 Story 的扫描与领取，确认新快照已启用。正式账本升级后，#34、#35 保留旧快照，补建任务数为 0。每小时接单任务已核实处于启用状态。
- 纯前端三项、纯后端四项的单端演练也已通过，各项在验收、合回后独立关闭；原 Task 客户端的 97 项回归测试全部通过。
