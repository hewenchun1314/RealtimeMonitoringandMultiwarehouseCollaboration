# 禅道无人值守研发

## 监测入口

从项目根目录运行 `python -B .agents/skills/zentao-autodelivery/scripts/monitor.py --once`，常驻监测用 `--watch`。该入口处理分页扫描、队首复核、名额、派单和持久待回写队列。项目/产品范围、指派人白名单及各类状态取自项目配置。实例、原单类型和 ID 决定备注与附件归属。

首次完整扫描建立历史基线。部分扫描保留已有队列。领取 Story 前按配置核对需求 Git 上游。首次派发只创建回复就绪的会话，从真实回执绑定后才恢复该会话开工。启动或发送结果不明时核对原操作与既有证据。查看账本同目录的 `status.html` 与 `items/<marker>/dispatch.log`。

## 工单执行入口

涉及页面的需求和 Bug，材料检查和测试 Agent 都读取[前端 E2E 公共操作手册](../../../docs/前端E2E操作手册.md)。从禅道原单描述提取本单的页面、操作、数据条件和预期结果。原单允许任意样本时，选择实际有数据的案例和井，记录实测值。

1. 通过[账本命令](references/workflow-cli.md)核对原单、派单编号和实际会话，无人值守权限为 `never` 时领取执行权。已有尝试先核对阶段、负责人、截止时间、工作树和原回执。
2. 按[阶段指引](references/stages.md)和账本的实际步骤执行。用 `monitor.py --materials <marker>` 读取领取时留存的需求描述、验收标准、Bug 复现步骤和附件索引。Story 使用统一 Git 入口同步材料并记录提交号；缺少材料或关键输入时写明所缺内容和本地证据。材料齐全的 reviewing 或 active 需求可进入本地拆分。Bug 核实复现、预期、实际结果与影响范围。
3. 按单内的范围组织前后端设计、计划、编码、单测和独立代码审查。拆分项、依赖、阶段及验证证据在本地登记。代码审查逐仓比较基线与候选提交，保留定位、严重度及测试证据。
4. 用[统一 Git 入口](references/branches.md)请求分支、工作树、候选提交和合回。主会话在同一轮读取结果，使用稳定操作标识。开发阶段只编辑、构建和测试。验收入口见[后端](references/backend.md)和[前端 E2E](references/e2e.md)。需要宿主 E2E 或发布时按对应回执交还执行权，随后沿原会话继续。
5. 以实际提交、端口状态、页面资源、服务和镜像版本作为本次验收证据。确认停止和结果后登记阶段。遇到环境暂时不可用或本次运行结果未知，先核对原请求；独立项可继续。到收尾时汇总真实交付和未验证事项，并提交 `record complete`，必要时附本单 `blockers.md`。监测进程向原 Story/Bug 写备注和上传附件，随后读回。使用进度页核对本地结论及待回写状态。

## 工单材料与流程冲突

业务材料用于判定开发范围、复现步骤和验收条件。工作树、分支、合回、推送与部署均按项目授权配置、工单快照和账本阶段操作。涉及外部依赖时，核对当前配置与领取快照的一致性。步骤 Agent 的运行由[阶段运行器](references/stage-runner.md)监管，核实超时清理后再重试。阶段无法完成时保存原因和证据，按账本继续可执行步骤。

启动命令、凭据与平台验证见[项目说明](../../../README.md)和[启动器说明](references/worker.md)。
