# 禅道建单与材料留痕

## 标准需求提交：只填写目录标识

用户要求提交需求时，标准动作只有：读取配置和已准备的仓库材料、保存本地建单记录、创建Story、回读并保存本地回执。需求正文仅填写一行 `ZT-123/`（使用实际目录标识）；标题、项目、指派等禅道原生必填字段正常填写，不在正文附加解释。默认不上传附件、不追加索引或评论、不创建Task/Bug、不执行建单前业务评审。附件和补索引仅在用户另有明确要求时执行，不是标准提交或需求评审的完成前提。

提交到配置项目并指派给配置账号，是小D后续接收和派发需求评审的入口。小D通过定时查询发现、持久化接收，再在对应需求项目下新建Codex对话评审；创建成功不等于评审已开始，也不依赖Webhook。Codex不得再自行启动一轮重复的需求评审或澄清审批。

接收前，用户授权的Codex可准备并创建条目、上传材料、保存回执及补充文件索引；不必由小D代做。小D持久化接收后，该需求的禅道查询、写入、补附件和结果不明对账均由小D统一处理，其他agent仅准备本地产物并回传。接收状态未知且操作既有条目时先向本地接收记录核实，无法核实则只准备，不冒险写入；不在接收后向人提问。

本技能提供操作规则，不附禅道API客户端。先读 [操作与回执](references/operations.md)，使用当前可用且获授权的连接器；不足时使用浏览器/电脑操作并遵守对应技能。没有可用访问能力或凭据时明确报告未执行，不能照搬旧仓库脚本；旧脚本的三文件检查、确认门槛、绝对路径索引和正文标记不适用于本规范。

## 选择项目、人员与类型

读取工作区 `.agents/workflow.json` 指向的项目映射及接收配置；引用路径相对该文件，工作区路径相对项目配置文件。按当前仓库匹配唯一项目；项目与账号每次从配置读取，不硬编码。账号大小写保留，登录账号不等于指派账号。配置多个接收账号时，用用户指定且匹配的账号；无唯一选择时接收前仅询问这一缺项。API要求产品/迭代等必填值时先只读核实，不能猜ID或改变用户请求的类型。

- 当前自动接收入口是研发需求/Story。用户说“提交这个需求到禅道”，创建Story，正文只写目录标识。
- 用户明确要求Task时创建Task；Bug时创建Bug，不自动附带修复任务。不把Task/Bug声称为当前已支持的自动接收入口。
- Task/Story产品归属、项目归属及迭代关联能力须真实核实；不支持时说明具体缺项，不悄悄换类型。

## 准备与操作

1. 创建需求Story或基于该需求的Task时，读取目标目录，确认intent.md存在、可读；AC.md可选，不因缺失而阻塞建单。创建Bug不要求需求文件，按第2步整理复现证据；独立于需求的Task按用户任务内容准备，不强加需求文件。未决业务不阻塞建单，不要求REQ.md、业务全文确认、正式编号、接口就绪或独立测试。当前需求Story入口标准要求先有本机可读取的固定材料commit；尚未提交或所需同步未完成时可以准备计划，不声称完成标准入口提交。若当前任务已包含材料编写/评审及相应Git授权，则提交本次改动：有远端时完成所需同步和push并核验，无远端时核验本地commit，远端操作记not_applicable，不要求添加远端；纯建单不擅自提交其他改动。Bug和独立Task不强制需求仓库commit，不虚构版本。
2. Story正文精确为 `ZT-<编号>/`，标题等原生必填字段照常填写。不要在正文附业务全文、文件索引、版本、幂等标记或审批状态。需求标题不得影响目录定位。Task按明确任务内容填写，Bug记录实际复现、期望/实际、环境及证据，不强制需求文件。
3. 建单前先保存本地操作记录与稳定operation_id，查询已有回执和当前目标中的候选条目。准确绑定实例、项目、类型及适用的目录标识和commit；Bug/独立Task不适用的目录、commit明确留空，不据此阻塞，不只按标题猜测；同一请求已有条目时回读复用，不能因附件失败或重启创建副本。
4. 已有明确建单授权且计划与请求一致时直接执行，无需再次确认发布。只有确实缺必要信息或歧义才在接收前询问。写请求超时/结果未知时先读回对账，不盲重试，不删除或重建；无法唯一确认则保存unknown并停止该动作。
5. 按请求或预置提交策略上传本次材料快照。附件仅包含选定需求材料或该Bug/独立Task的实际证据；保留相对路径、适用的真实commit及SHA-256清单，不适用的目录标识和commit留空。上传前确保关联正确、无凭据或敏感数据；不打包整个仓库、.git、技能目录或本地运行记录。必需附件未核验则条目已创建但未完成本次提交，不能报告complete。
6. 文件索引只写入评论/备注：仓库目录标识、相对文件路径、真实commit、附件内路径及哈希。明确要求补充已有条目索引时才追加；若平台只能改正文，保持Story正文规范并报告不支持，不偷偷追加。小D已接收则交给小D执行补充。
7. 回读标题、类型、项目、指派账号、Story正文及本次必需附件关联，保存回执与条目链接。未核实外部效果不得报告成功，也不把建单当成小D接收或开发开始。

加载技能或存在配置不自动授权实际建单、上传、外发或修改状态；实际操作依据当前请求及有效的既有授权，明确授权后不重复询问。

AC.md为可选产物；未提供时不自动要求生成，不阻塞评审、建单或后续任务准入。仅在用户需要时编写，已有文件则维护引用一致。

接收后适用最新无人交互规则：AI自主判断、记录依据，不能完成则记录问题并跳过受影响项，继续至自动收尾，不询问人或等待确认。接收前的提问仅用于用户主动编写/提交需求，不能套入小D接收后的流程；接收后禅道操作仍仅由小D执行。
