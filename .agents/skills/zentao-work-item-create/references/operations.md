# 操作与回执约定

标准需求提交仅创建正文为目录标识的Story并保存本地回执，不做附件或索引步骤；以下快照、附件与评论操作仅适用于另有明确请求的场景。标准建单后的回读属于确认本次创建结果；若已明确获知小D接管，则由小D提供结果，不再发起新外部操作。

## 配置和权限

读取工作区 `.agents/workflow.json`：`project_config_ref` 指向项目映射，`intake_config_ref` 指向禅道连接配置。项目名称/工作区/账号取对应projects项；实例和credential_ref取接收配置zentao项。enabled控制小D轮询，不表示Codex接收前的显式建单被禁止或已经授权。地址、凭据引用未配置时不使用旧仓库或历史对话的默认值。凭据引用解析能力未提供时报告缺项；不把密码或令牌写进工作区。

先发现连接器可用的查询、创建、附件和评论工具；不臆造工具或API。若使用浏览器，检查真实表单及回读页面；已有登录只提供访问条件，不扩大操作授权。记录实际能力缺口。只能准备材料时报告prepared，不报告已创建。此技能没有捆绑旧API脚本或配置向导，不给出不存在的命令。

## 接收边界与本地存放

接收边界是小D已持久化该条目接收记录，不是创建成功或指派到配置账号。Codex首次创建前无需证明尚不存在的条目未被接收；拿到ID后的附件/索引/重试前重新核实接收记录。接收状态来自小D的持久记录或其明确结果，不以“本地没回执”推断未接收。无法读取权威记录时停止后续写入，保留待处理；由小D接收后补齐。

操作记录存 `requirements/<标识>/.local/zentao/operations/<operation_id>.json`，回执保存其关联ID；Bug没有需求目录时使用工作区 `.local/zentao/`。这些文件为本机运行记录，不是需求必需文件，不进入材料快照或Git。创建前用原子文件替换持久化稳定operation_id、请求摘要和状态；重试继续同一ID，不按时间生成新的业务操作。业务记录使用配置工作区＋目录标识＋材料版本定位；禅道接入层在其内部回执保存接口返回的对象编号/链接供读写对账，不向评审或开发agent要求该编号，不依赖标题。

## 接收记录定位

通过 `.agents/workflow.json` 的intake_config_ref读取接收配置，再按其persistence.path定位SQLite；路径相对接收配置文件目录。不得在技能中固定数据库绝对位置。使用SQLite只读连接，先查看sqlite_master和表结构，再按“配置需求工作区＋目录标识”查询已持久化业务接收记录；外部对象编号的关联与查询仅由接入层内部处理；任一版本/轮次已被小D接收就按小D接管处理，不只匹配本次本地commit。不得新建数据库、修改接收表或抢占小D锁。

当前接收器与表结构尚未实现，因此此定位规则不代表已经具备可靠的接收状态查询能力。数据库不存在、无法读取、没有可识别字段或无法确认查询覆盖全部记录时，状态是未知，不是未接收；先保存待上传/待补索引记录，交由小D后续接收恢复。若宿主提供经核实的接收状态查询接口或小D明确回执，可替代SQLite读取并记录证据。后续接收器实现须提供按配置需求工作区和目录标识可核验的业务接收记录读取能力；未实现前不声称附件闭环已经跑通。

## 快照

默认只准备快照；是否上传取本次请求或明确的提交策略。用户要求上传时，intent.md、已提供的可选AC.md及选定assets文件可组成ZIP（不因缺少AC.md而阻塞），manifest.json登记仓库目录标识、真实commit、文件相对路径、字节数及SHA-256。记录快照文件本身的SHA-256。不包含.local/、凭据、软链接逃逸目标或无关需求。附件可作为版本证据，当前需求Story入口仍要求仓库有可同步commit，不以ZIP假称已推送；Bug/独立Task可使用实际截图、日志等证据及哈希，目录标识和commit不适用时留空，不强加需求仓库commit。

上传后确认附件属于本实例本条目；仅上传接口成功不等于关联成功。必需附件失败：记录created_pending_attachment；结果未知：unknown，先对账。不重复创建主条目。冻结附件不覆盖，新材料使用新快照和对应版本。

## 回执字段

记录以下真实数据，未执行/未知明确区分，不填伪造ID：

- schema_version、operation_id、action、request_digest、status、实际时间。
- 实例、项目标识、类型、指派账号、适用的仓库目录标识、材料commit及相对文件清单；Bug/独立Task不适用字段可为空。
- 接入层内部对象编号/链接、创建请求结果和读回证据；Story正文读回结果。此项只用于接入层对账，不是业务任务输入或评审回传要求。
- 附件名称/ID/哈希/关联核验、评论/索引标识及核验结果。
- intake_owner（codex_pre_intake或dot）、已执行动作、待处理动作、错误及恢复条件。

status使用prepared、creating、created_pending_attachment、complete、blocked、unknown。complete必须满足本次实际请求的全部外部动作及读回；不要求本次未请求的附件或索引。副作用未知不能记为未执行。

Story正文禁止嵌入DOT-OP等标记。幂等标记可在平台独立字段或评论承载；使用前核实能力。未成功写入标记的创建若结果未知，只能按回执、条目ID或完整分页候选对账。相同目录可能有不同版本、不同任务，无法唯一归因时不重发，保存unknown。

## 不新增自动化入口

本技能可按明确请求创建Task和Bug，但当前小D入口仍为Story；不自动建修复任务、关闭条目、变更状态、轮询运行或派发开发。接收后外部操作必须由小D执行。
