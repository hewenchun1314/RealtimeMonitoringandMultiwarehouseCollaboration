# E2E 环境准备与取证

E2E 在合回前执行。从工单配置快照读取 `e2e` 设置及当前前端开发仓库。基座准备、登录、选工区和场景验证共同使用本次 E2E 的单次最长耗时，当前配置为 90 分钟。

Windows 工单启动器未提供已连接的浏览器工具时，使用已安装的 Playwright 和独立测试浏览器会话，纳入当前阶段运行器。若执行入口或凭据不可用，按本节登记验证阻断并继续收尾。

## 基座应用

1. 根据 `e2e.ready_url`、已打开的业务页面或启动设置识别前端地址。服务已启动时直接复用。优先查看已登录的浏览器页面及应用内导航。需要额外做 HTTP 探测时，页面请求显式使用 `Accept: text/html`，例如 `Invoke-WebRequest -Uri $browserEntry -Headers @{ Accept = 'text/html' } -TimeoutSec 8 -SkipHttpErrorCheck`。缺少 `Accept` 或按 JSON 请求的深层路由可能返回 `404`，应以实际浏览器访问和页面功能作准备结论。HTML 返回 `200` 仅证明前端入口可访问。
2. 确认服务尚未启动时，才从本单 worktree 对应的基座目录执行 `e2e.start_command`。本次启动的服务纳入当前尝试的受控进程登记。`ready_url` 为空时，从本次启动输出或现有浏览器页面确认前端入口。网关参数用于启动配置。
3. 记录复用服务的实际工作区和能核验的代码版本。涉及子应用时，核对基座加载的子应用。运行中的版本和候选版本无法证实一致时，仍执行可做的现有页面验证，单独记录结果，并注明候选版本仍待验证。合回使用可追溯到本单待验代码的验证证据。
4. 入口或场景无法执行时记录阻断，继续其余可执行的场景、报告和回写。保留复用的会话、工区、服务及用户已有待保存操作。超时按 [受控停止](stages.md#超时和受控停止) 处理本次自有资源。

## 登录和工区

1. 从实际基座前端地址解析配置的 `e2e.login.path` 和 `e2e.platform_entry_path`，核实页面属于本单测试目标。已有配置账号的有效登录就直接复用。项目配置的 `login` 为 null 且测试入口公开时直接进入。需要登录且未登录或会话过期时才打开登录页，从本机凭据读取密码并登录。其他账号在独立的测试会话中处理，保留用户原会话。
2. 当配置的 `default_work_area` 为 null 且产品无需选择工区时，直接验证业务入口。需要选工区的项目读取配置。已有选中工区时直接沿用，包括登录后平台自动恢复的工区。当前会话没有工区时，在平台首页按 `e2e.default_work_area.id` 选择配置的默认工区，确认选中生效后再进入菜单。已有工区即使与默认配置不同也以实际当前工区为准。
3. 因地址、登录或工区准备受阻时，记录实际失败的环节和必要证据。重试从环境检查开始，逐项复用已经就绪且仍符合版本及会话要求的部分。

## 验收结果

按 `plan.md` 中的验收条件执行实际业务场景。保存基座前端入口、启动工作区、待验代码版本、实际工区、每个场景结果以及证据位置。使用测试数据，屏蔽截图和日志中的密码、会话凭据和无关业务数据。环境未能就绪或无法证明待验版本时，将本单收尾为待验证，保留已通过的单测和审查证据。
