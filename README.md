# 海能发地质工程一体化 · 禅道无人值守研发

本仓库用于协调禅道工单、需求材料和多个业务代码仓库。Codex 桌面的监测会话负责发现和排队，每张领取的工单绑定一个专属会话，负责拆分任务、组织开发与独立验证、逐仓合回代码，并将实际结果写回原禅道工单。

## 提交一条前端需求

1. 在需求仓库 `req-demo/requirements/` 下为需求建立目录，写好 `intent.md`，说明要解决的问题、期望行为和可核对的验收条件。规格、截图和其他附件放在同一目录。
2. 在禅道「海能发地质工程一体化」项目中新建需求，在描述中写明材料目录，指派给 `DOt-hwc`。当前配置接收状态为 `reviewing` 或 `active` 的需求。提交 Bug 时，在原单中写明复现步骤、期望结果和实际结果，并指派给同一账号。处于 `active` 状态的 Bug 会进入接单扫描。
3. 首次完整扫描会登记已有工单作为历史基线。后续扫描发现符合条件的新单后，按禅道优先级排队，同级按发现顺序处理。当前同时执行一单。
4. 在原禅道需求的备注中查看各阶段结果和最终结论。若结论为「待补材料」，可按备注中的缺失路径补齐文件。

## 配置监测

运行前先打开[项目配置](.agents/zentao-project.json)，核对以下设置。

| 配置项 | 核对内容 |
| --- | --- |
| `zentao` | 禅道实例、项目名称、接单账号和接收状态。确认本机能解析 `credential_ref` 指向的凭据。 |
| `workspaces` | 需求仓库和前端代码仓库须在本机就位。路径从配置文件所在的 `.agents/` 目录解析，当前分别指向项目根目录下的 `req-demo/` 和 `aggregation-platform-4/`。 |
| `runtime.sync_requirement_before_review` | Story 每次材料评审前，从需求仓库当前分支的上游拉取并快进。同步成功后开始评审，同步失败按原阶段重试。 |
| `development` | 核对允许的研发范围、并发数，以及每个应用对应的仓库和目标分支。新领取的工单使用当前配置，已领取的工单沿用领取时的快照。 |
| `e2e` | `enabled` 控制新领取工单是否执行前端页面验收，当前为 `false`。关闭时跳过页面验收，继续合回。重新开启时设为 `true`，并核对启动命令、登录凭据引用和默认工区。 |
| `monitor`、`runtime` | 将 Codex 桌面定时任务绑定到对应项目的监测会话。当前配置启用监测，期望间隔为 60 分钟，实际唤醒时间由桌面定时任务决定。 |
| `runtime.split_task_sync` | 开启后，新领取的 Story 每个拆分项在原迭代创建一张 Task，初始指派给原需求当前指派人。各项满足本单验证要求且相关仓库全部合回后关闭。关闭前端页面验收时，前端任务以当前候选的单测、代码审查和实际合回证据收尾。迭代待定时先推进研发，归属明确后补建。 |

监测会话按[自动交付操作说明](.agents/skills/zentao-autodelivery/SKILL.md)执行扫描、队首复核和派单。工单会话在材料检查、任务拆分和分支核验后，安排开发和单测，再由测试 Agent 审查代码并做验收。各应用的候选提交、测试结果和实际合回版本随单归档。

## 查看运行结果

| 想查什么 | 位置 |
| --- | --- |
| 哪张单正在执行、排队或等待回写 | 运行后用浏览器打开本机的 `.local/zentao-delivery/status.html`。 |
| 某项拆分任务是否已关闭 | 在本机进度页展开任务列表，查看研发结论、禅道实际状态和待同步原因，点击 Task 编号查看原迭代中的任务。 |
| 某张单的设计、计划、测试证据或阻断原因 | 查看 `.local/zentao-delivery/items/<marker>/`，其中 `<marker>` 是账本为该工单分配的目录名。 |
| 会话绑定、阶段尝试和禅道回执 | 本机 SQLite 账本位于 `.local/zentao-delivery/workflow.sqlite3`。禅道暂时不可用时，待回写项保存在账本中，供后续轮次核对和补发。 |
